# Практическая работа № 11. Алгоритмы замещения страниц

## 1. Цель работы

Изучить принципы виртуальной памяти и подкачки страниц, реализовать алгоритмы замещения страниц, сравнить их эффективность и исследовать поведение памяти в Linux.

В работе выполнены три части:

- **Часть A.** Реализация алгоритмов замещения страниц на Python.
- **Часть B.** Эксперименты с локальностью обращений и аномалией Белади.
- **Часть C.** Исследование реальных обращений к памяти с помощью программы на C.

## 2. Теоретические сведения

### Виртуальная память

Виртуальная память позволяет процессу использовать адресное пространство, которое операционная система отображает на физическую память.

Память разделяется на блоки фиксированного размера — **страницы**. Физическая память разделяется на блоки такого же размера — **кадры**.

Когда процесс обращается к странице, которой нет в оперативной памяти, возникает **page fault (страничное прерывание)**. Операционная система должна загрузить необходимую страницу. Если свободных кадров нет, требуется выбрать страницу для замещения.

### Алгоритмы замещения страниц

В работе реализованы четыре алгоритма:

| Алгоритм | Принцип работы |
|---|---|
| FIFO | Удаляет страницу, которая находится в памяти дольше остальных |
| LRU | Удаляет страницу, к которой дольше всего не обращались |
| Optimal | Удаляет страницу, которая понадобится позже остальных |
| Clock | Использует циклический указатель и бит обращения для выбора страницы |

**Optimal** служит теоретическим ориентиром: он использует информацию о будущих обращениях и не может быть непосредственно реализован в обычной операционной системе.

### Аномалия Белади

Аномалия Белади — явление, при котором увеличение количества кадров приводит к увеличению количества страничных ошибок.

Она может возникать в FIFO. Алгоритмы со свойством стека, например LRU и Optimal, такой аномалии не имеют.

## 4. Часть A. Реализация алгоритмов

В файле `replace.py` реализованы:

1. FIFO.
2. LRU.
3. Optimal.
4. Clock.

Каждый алгоритм получает последовательность обращений к страницам и количество доступных кадров.

Программа определяет:
- попадания в память (Page Hit);
- страничные ошибки (Page Fault);
- общее количество страничных ошибок.

### Проверка алгоритмов

Для контрольной последовательности обращений при трёх кадрах получены следующие результаты:

| Алгоритм | Page Fault |
|---|---:|
| FIFO | 15 |
| LRU | 12 |
| Optimal | 9 |
| Clock | 14 |

При четырёх кадрах:

| Алгоритм | Page Fault |
|---|---:|
| FIFO | 10 |
| LRU | 8 |
| Optimal | 8 |
| Clock | 9 |

Результаты показывают, что Optimal имеет наименьшее количество ошибок на данной последовательности.

## 5. Часть B. Эксперименты

### 5.1. Сравнение алгоритмов при разном количестве кадров

Проведён эксперимент с количеством кадров от 1 до 8.

| Кадры | FIFO | LRU | Optimal | Clock |
|---:|---:|---:|---:|---:|
| 1 | 20 | 20 | 20 | 20 |
| 2 | 15 | 17 | 13 | 15 |
| 3 | 15 | 12 | 9 | 14 |
| 4 | 10 | 8 | 8 | 9 |
| 5 | 9 | 7 | 7 | 9 |
| 6 | 6 | 6 | 6 | 6 |
| 7 | 6 | 6 | 6 | 6 |
| 8 | 6 | 6 | 6 | 6 |

**Вывод:** при увеличении количества кадров количество страничных ошибок в большинстве случаев уменьшается. Однако FIFO может демонстрировать аномалию Белади.

График: `results/page_faults.png`.

### 5.2. Эксперимент с аномалией Белади

Использована последовательность:

```text
1 2 3 4 1 2 5 1 2 3 4 5
```

Сравнение результатов:

| Алгоритм | 3 кадра | 4 кадра |
|---|---:|---:|---:|
| FIFO | 9 | 10 |
| LRU | 10 | 8 |
| Optimal | 7 | 6 |
| Clock | 9 | 10 |

У FIFO при увеличении количества кадров с трёх до четырёх число ошибок увеличилось с 9 до 10. Это пример аномалии Белади.

Clock в данной реализации также показал увеличение количества ошибок. Это возможно, поскольку Clock не обладает свойством стека.

График: `results/belady.png`.

### 5.3. Локальность обращений к памяти

Проведено сравнение двух типов последовательностей:

- **Locality** — обращения преимущественно к ограниченному набору страниц.
- **Random** — случайные обращения к страницам.

Размер последовательности — 1000 обращений, количество кадров — 5. Для случайной последовательности использован `random_state = 42` (seed).

| Алгоритм | Locality | Random |
|---|---:|---:|
| FIFO | 438 | 761 |
| LRU | 398 | 763 |
| Optimal | 233 | 486 |
| Clock | 420 | 767 |

**Вывод:** последовательность с локальностью обращений показала меньше страничных ошибок. Это связано с тем, что программа чаще использует ограниченный набор страниц, которые могут оставаться в оперативной памяти.

График: `results/workload_comparison.png`.

## 6. Часть C. Исследование памяти в Linux на C

В файле `vm_experiment.c` реализована программа для исследования влияния порядка обхода массива на производительность.

Программа поддерживает два режима:

- `rows` — обход массива по строкам;
- `cols` — обход массива по столбцам.

Для измерений используются:

- `getrusage()` — получение статистики использования ресурсов процесса;
- `ru_minflt` — количество minor page faults;
- `ru_majflt` — количество major page faults;
- `gettimeofday()` — измерение времени выполнения;
- `/proc/self/stat` — получение статистики процесса из Linux.

### 6.1. Сравнение обхода по строкам и столбцам

Матрица размером 2048 × 2048 занимает 16 MiB при использовании элементов типа `int`.

Результаты:

| Параметр | По строкам | По столбцам |
|---|---:|---:|
| Размер матрицы | 2048 × 2048 | 2048 × 2048 |
| Minor faults | 4098 | 4098 |
| Major faults | 0 | 0 |
| Время | 0.056812 с | 0.155817 с |
| Checksum | 8585740288 | 8585740288 |

Обход по столбцам оказался примерно в 2,74 раза медленнее.

**Причина:** в языке C двумерные массивы хранятся построчно. Поэтому последовательный обход по строкам лучше использует кэш процессора и пространственную локальность.

### 6.2. Исследование размера памяти

Дополнительно выполнен эксперимент с матрицей 4096 × 4096.

| Параметр | Значение |
|---|---:|
| Размер матрицы | 4096 × 4096 |
| Объём памяти | 64 MiB |
| Minor faults | 16386 |
| Major faults | 0 |
| Время | 0.229738 с |

### 6.3. Ограничение доступной памяти

Для проверки поведения программы при ограничении виртуальной памяти использовалась команда `ulimit -v`.

При ограничении 96 MiB выделение матрицы размером 64 MiB прошло успешно.

При ограничении 32 MiB программа не смогла выделить необходимую память и вывела сообщение:

```text
Cannot allocate memory
```

### 6.4. Ограничения эксперимента

Во время проведённых запусков major page faults не наблюдались. Поэтому реальное состояние thrashing (интенсивной подкачки страниц) воспроизвести не удалось.

Также в используемой среде WSL2 не обнаружены интерфейсы:

```text
/sys/kernel/mm/lru_gen/enabled
/sys/kernel/mm/lru_gen/min_ttl_ms
```

Поэтому эксперимент с настройками MGLRU в этой среде выполнить не удалось.

Результаты C-экспериментов находятся в `reports/c_experiment.txt`.

## 7. Установка и запуск

### Требования

- Ubuntu / Linux или WSL2.
- Python 3.
- GCC.
- Библиотека Matplotlib.

### Шаг 1. Перейти в каталог проекта

```bash
cd ~/practicals/practical-11
```

### Шаг 2. Создать виртуальное окружение

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### Шаг 3. Установить зависимости

```bash
pip install -r requirements.txt
```

### Шаг 4. Запустить Python-эксперименты

```bash
python3 replace.py
```

После выполнения программа выводит результаты алгоритмов, сохраняет графики в `results/` и обновляет файл `reports/experiment_results.txt`.

### Шаг 5. Скомпилировать программу C

```bash
gcc -Wall -Wextra -O2 vm_experiment.c -o vm_experiment
```

### Шаг 6. Запустить эксперименты C

Обход по строкам:

```bash
./vm_experiment rows 2048 2048
```

Обход по столбцам:

```bash
./vm_experiment cols 2048 2048
```

Матрица большего размера:

```bash
./vm_experiment rows 4096 4096
```

В ходе практической работы были изучены и реализованы основные алгоритмы замещения страниц виртуальной памяти.

Полученные результаты позволяют сделать следующие выводы:

1. FIFO прост в реализации, но может демонстрировать аномалию Белади.
2. LRU учитывает историю обращений и в проведённых экспериментах показал хорошие результаты.

4. Clock является приближённым алгоритмом, который использует бит обращения и циклический указатель.
